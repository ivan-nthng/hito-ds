# Media landing recipe

The Hito home page composes the existing library: `Text`, `Card`, `Breadcrumbs`, `Button`, `Link`, `Tag` and `Separator`. Its dark neutral outer page and explicitly light raised Card demonstrate independent theme and color-scheme scopes. Card defaults and existing component APIs are unchanged.

The additive `Dot`, `Live`, `MediaBackdrop`, `RoundPlayButton`, `MediaActionLink` and `MediaFooter` helpers live in the React package. `RoundPlayButton` wraps the native XL primary/accent Button; `MediaActionLink` remains a real anchor. `MediaFooter` derives a normal-flow full-bleed divider from the fixed compact Card's inset. Consumers own destinations, accessible action labels and state.

`Live` animates only its semantic success dot from opacity 1 to .45 and back every 1.92 seconds, continuously. `prefers-reduced-motion: reduce` leaves a static dot and label. The six-object background is a fixed, largest-viewport-backed decorative layer with safe-area coverage; foreground content stays in ordinary scroll flow. Its field is taller (144% desktop/160% mobile) so the retained forms extend higher. Existing SCREEN blending, palette, mask and source blur remain. The original256px SVG tile is displayed at384px/.22 opacity for larger, clearer grain.

Six asynchronously phased transform-only animations gently drift, rotate and breathe over96-second cycles. Grain translates one exactly repeating tile over96 seconds on a horizontally overscanned composited layer, without opacity flashing or per-frame React updates. `prefers-reduced-motion: reduce` stops both while preserving the enlarged visible composition. Live retains its separate1.92-second normal/static-reduced behavior. Static blur is never animated. These long decorative timings are separate from UI feedback timings.

Existing semantic diffuse scrim paint protects mobile intro, intrinsic attribution and footer where larger moving colors would otherwise reduce contrast. It changes neither foreground type/content/layout nor the field globally. The viewport meta permits cover and zoom; existing page spacing respects safe-area insets. A largest-viewport fallback covers controllable page paint during viewport-height changes, but a website cannot paint native iOS browser/toolbars outside its view. Browser-engine verification is separate from physical iPhone/in-app-host toolbar confirmation.

Geometry, opacity, texture and eight additive ambient/coverage parameters remain in the single bounded `tokens/media-recipe.mjs` group, exported as `@hito-ds/react/tokens/media-recipe`; no new general palette, public React API or dependency. Regenerate with `node packages/design-system/tokens/build-media-recipe.mjs`, then validate tokens. The old document-overhang parameter remains neutral/reserved and unused.

The site owns the original coastal photograph export and synthetic session content. The served JPEG removes metadata without re-encoding the image; its adjacent provenance JSON records hashes. This asset belongs to the site, not the component package. Play/Pause changes demonstrative local state without streaming audio, Save is reversible for the current visit, and View Tracklist opens a local accessible disclosure. Nothing is submitted or remotely stored.

At the approved desktop/mobile widths, the Card is 448/358px wide with a centered 3:2 photo. Local radius and inset parameters retain the approved composition while leaving shared Card behavior intact. The narrow layout wraps tags, actions and navigation naturally.

Build with `npm run build` and validate the composed artifact with `npm run verify:site`. To replay against an already serving deployment, use `npm run verify:site -- https://www.hitocajon.com` (only after that deployment contains this recipe). The verifier checks root and nested Storybook navigation, assets, real missing-file responses, keyboard access, local control states, actual fonts, repeated Live beyond the native finite-export duration and reduced motion. For optional installed WebKit coverage run `HITO_VERIFY_WEBKIT=1 npm run verify:site`. The motion checks compare actual changing frames, equivalent controlled phases across scroll/expansion/resize, complete cycle closure, covered grain edges and reduced-motion static output. Synthetic safe-area checks use Chromium protocol emulation; none is physical-device evidence. It also checks package isolation and preserved public exports. This verification does not assert automatic Figma synchronization.
