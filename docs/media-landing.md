# Media landing recipe

The Hito home page composes the existing library: `Text`, `Card`, `Breadcrumbs`, `Button`, `Link`, `Tag` and `Separator`. Its dark neutral outer page and explicitly light raised Card demonstrate independent theme and color-scheme scopes. Card defaults and existing component APIs are unchanged.

The additive `Dot`, `Live`, `MediaBackdrop`, `RoundPlayButton`, `MediaActionLink` and `MediaFooter` helpers live in the React package. `RoundPlayButton` wraps the native XL primary/accent Button; `MediaActionLink` remains a real anchor. `MediaFooter` derives a normal-flow full-bleed divider from the fixed compact Card's inset. Consumers own destinations, accessible action labels and state.

`Live` animates only its semantic success dot from opacity 1 to .45 and back every 1.92 seconds, continuously. `prefers-reduced-motion: reduce` leaves a static dot and label. The six-object background now has a full-document paint carrier mounted beside the foreground page at the site root. A private site adapter keeps its ordinary absolute, overflow-visible composition aligned with the viewport using passive scroll/resize events and coalesced direct transforms (no continuous JS animation/React state); the carrier and static grain continue wherever document foreground is rendered, rather than ending at a fixed/sticky viewport-constrained box. Root html/body/#root canvas propagation is explicit. Foreground stays in ordinary scroll flow. The retained field is144% desktop/160% mobile, with existing SCREEN blending, palette and source blur. The same top-fade parameters now paint black-to-transparent above the forms instead of alpha-clipping their overflow at a viewport-sized mask edge.

Six asynchronously phased transform-only animations gently drift, rotate and breathe over96-second cycles. Grain is deliberately static, finer/quieter at256px/.12 using the original texture: sideways translation, extra tile overscan and grain promotion were removed after the actual iPhone failure report. The exported grain-cycle parameter is reserved/inactive for compatibility. `prefers-reduced-motion: reduce` also stops the forms while preserving the visible composition; Live retains its independent rule. Static blur is never animated.

Existing semantic diffuse scrim paint protects mobile intro, intrinsic attribution and footer where larger moving colors would otherwise reduce contrast. It changes neither foreground type/content/layout nor the field globally. The viewport meta permits cover and zoom; existing page spacing respects safe-area insets. The viewport sizer uses the largest-viewport fallback, but does not clip the colored overflow or limit the document paint carrier. An actual iPhone report failed the earlier fixed-layer solution while Card/photo continued below its cutoff; that failure is not dismissed as native chrome. Browser-engine verification remains separate from same-host physical iPhone confirmation.

Geometry, opacity, texture and eight additive ambient/coverage parameters remain in the single bounded `tokens/media-recipe.mjs` group, exported as `@hito-ds/react/tokens/media-recipe`; no new general palette, public React API or dependency. Regenerate with `node packages/design-system/tokens/build-media-recipe.mjs`, then validate tokens. The old document-overhang parameter remains neutral/reserved and unused.

The site owns the original coastal photograph export and synthetic session content. The served JPEG removes metadata without re-encoding the image; its adjacent provenance JSON records hashes. This asset belongs to the site, not the component package. Play/Pause changes demonstrative local state without streaming audio, Save is reversible for the current visit, and View Tracklist opens a local accessible disclosure. Nothing is submitted or remotely stored.

At the approved desktop/mobile widths, the Card is 448/358px wide with a centered 3:2 photo. Local radius and inset parameters retain the approved composition while leaving shared Card behavior intact. The narrow layout wraps tags, actions and navigation naturally.

Build with `npm run build` and validate the composed artifact with `npm run verify:site`. To replay against an already serving deployment, use `npm run verify:site -- https://www.hitocajon.com` (only after that deployment contains this recipe). The verifier checks root and nested Storybook navigation, assets, real missing-file responses, keyboard access, local control states, actual fonts, repeated Live beyond the native finite-export duration and reduced motion. For optional installed WebKit coverage run `HITO_VERIFY_WEBKIT=1 npm run verify:site`. The motion checks compare actual changing frames, equivalent controlled phases across scroll/expansion/resize, complete cycle closure, document paint below a counterfactual viewport cutoff, static grain and reduced-motion output. Synthetic safe-area checks use Chromium protocol emulation; none is physical-device evidence. It also checks package isolation and preserved public exports. This verification does not assert automatic Figma synchronization.

Desktop first-screen fit uses height-responsive outer spacing and breadcrumbs within the intro, preserving the stacked mobile order. The default Card, actions and attribution fit ordinary laptop viewports down to1280×640 CSS pixels. Only short desktop photographs crop vertically between160px and the accepted288px height; Live follows the same image bound. Typography, controls, content and mobile photo geometry stay native. Expanded content and zoom/reflow remain normal document scroll, with no internal Card scrolling. The site verifier asserts actual first-viewport Card/action/credit/header bounds across seven desktop sizes in Chromium and optional WebKit.
